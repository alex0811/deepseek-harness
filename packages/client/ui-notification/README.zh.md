# @deepseek-ai/dsh-client-ui-notification

[English](README.md) | 中文

## 概述

本包为 Web GUI 增加轮次提醒：当一个顶层会话停止运行，或发布了一个等待用户的交互请求时，页面播放一段简短提示音并发出系统通知，让用户不在别处时跑完的任务不至于无人察觉。两个触发条件与两条投递渠道各自是常规设置区块中的开关，由本包自己的设置行承载。窗口可见且聚焦时默认不打扰，除非用户打开该覆盖项；工作区浏览器的完成圆点已经标记了同一个状态跃迁，且不打断用户。subagent 会话永不提醒：它们运行在用户已经在跟踪的任务之下。

<a id="use-this-package"></a>
## 使用本包

把本插件与 Web profile 的其余部分一起挂载；常规设置区块中随即出现 **任务提醒** 行，此后只要页面具备相应能力，提醒无需额外配置即可生效。

### 提醒行

五个开关承载这些偏好：**任务完成时** 与 **等待我操作时** 决定触发条件，**提示音** 与 **系统通知** 决定投递渠道，**窗口在前台时也提醒** 决定用户正看着页面时是否允许打断。两个触发条件默认开启，两条渠道默认开启，前台覆盖项默认关闭，因此一个在别的窗口背后跑完的任务只会宣告一次。偏好是持久的：它们存放在宿主用户设置文档的 `ui-notification` 区块中，因此重新加载、另一个浏览器窗口与桌面端外壳读到的都是同一份答案。

### 浏览器通知权限

系统通知需要浏览器自身的授权，而页面只能在点击中请求它。答案尚未确定时，该行渲染 **允许浏览器通知**；授权后按钮消失，拒绝则以一行文字指向浏览器的站点设置。窗口每次重新获得焦点时该行都会重读权限，因此在浏览器设置中所做的改动无需重新加载即可显现。完全未提供 Notification API 的页面——例如内嵌 webview——两个控件都不渲染，提示音照常工作。

### 提醒说了什么

通知标题是会话的显示名称，正文说明结果：任务已完成，或会话正在等待输入或确认。同一会话的重复提醒会在通知中心互相替换，而不是逐条堆积。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

插件订阅 `ctx.uiSession.sessionStatus`——统一的按会话状态源——并把每次发布的快照交给一个状态跃迁检测器，后者只为每个会话保留上一次观测。会话的首次观测是基线，因此重新加载或重连重新发布的空闲会话保持静默；运行中的会话停止时检测器报告 `completed`，请求出现时报告 `awaiting-input`，替换的新请求同样如此。同一步既让会话停止又发布请求时只报告等待，因为它本身就在请用户行动。这个订阅是提醒的唯一输入：不轮询、不定时器，会话目录已不再承载的会话也不提醒。

随后投递要经过两道过滤才抵达页面。`reminderSubject` 解析会话的显示名称，并排除 subagent 会话与目录中缺席的会话；`ReminderPolicy` 读取实时偏好，并在页面可见且聚焦时跳过投递，除非覆盖项已打开。策略背后的渠道按需从页面自身的全局对象读取，因此从不提醒的页面不付出任何代价：系统渠道包装 `Notification`（权限逐次读取，横幅以 `dsh-session-<id>` 标签发布），声音渠道在首次提醒时创建的同一个 `AudioContext` 上排定一段双音正弦提示音，前台渠道读取可见性与焦点。任何能力缺失都退化为空操作而不是错误：没有音频的页面、被拒绝的横幅、没有 Notification API 的页面都保持静默，并各自记录一行 console。

该行经 `ctx.slots.inject` 注册进 `settings.general.item`，因此在本插件之后才声明该区块的组装仍然能安放这一行。它的注入面把实时的偏好与权限源放在 `hooks` 分区中；拨动开关会立即发布新值，并经 `ctx.settingsScope` 写入该字段，而作用域自身的接受会重新发布区块，使被拒绝的写入回退该行。提醒界面背后的决策及其放弃的东西记录在 [Web 轮次提醒 Agent Note](../../../.agents/notes/implemented/feature/2026-09-20-web-turn-reminders.zh.md) 中。

</details>

#### KV Cache 影响

无；本包从不组装或发送提供方请求。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制界定了当前的提醒界面。它们是当前包约束，不是通用通知方案对比或任务积压。

- **提示音是合成的，不可挑选**——两个触发条件播放同一段上行双音，因此听感上无法区分，也不读取用户提供的音频。首次 `AudioContext` 构造失败的页面在整个会话中保持关闭提示音，而不是逐次重试。
- **提醒不会把用户带到该会话**——横幅只携带会话名称；选中它不会聚焦任何东西，因为会话选择属于工作区浏览器，而本包不贡献任何导航。
- **只有「运行到空闲」这一步会提醒**——subagent 或后台任务在父会话保持空闲或持续运行时完成不会产生提醒，失败的会话与成功的会话正文相同；失败细节留在 transcript 中。
- **每个请求键只报告一次**——检测器比较待处理交互的身份，因此以新键重新发布同一请求的领域会再次提醒，而跨重连一直待处理的请求不会。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

提醒在构造上就是页面本地的：宿主只存偏好，别的什么都不存，因此桌面端外壳、本机浏览器与远程浏览器各自经自己的能力投递。提示音用 Web Audio 合成而不发布音频资源，这既让发布包保持为两个 bundle 产物，也避免了一个其许可与音量都无人评审的音频文件。

</details>

**运行时不变式：** 不发布伴生入口。本包把统一会话状态投影为页面本地提醒与一个设置行；它不持有跨插件可变状态，其 slot 注册与状态订阅都通过 HMR（热模块替换）安全性规范验证了资源释放行为。
